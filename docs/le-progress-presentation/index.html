Progress snapshot

Executive Summary

Phase 3 has moved CivitasWatch from basic operational screens toward a structured patrol, control room, register, reporting, and intelligence platform.

Operational

Patrol workflow

Mobile field workflow is active for starting patrols, capturing events, requesting assistance, and closing patrol sessions.

Operational

Control Room overview

Live overview, active patrols, assistance requests, incidents, directories, and patrol reports are available in the local Control Room workspace.

Persistent

Admin master registers

Master registers are backed by API/database persistence and use safe deactivate behavior for history-linked records.

Imported

SAPS incident codes

Numeric SAPS incident codes are imported with leading zeroes preserved and demo records disabled rather than deleted.

Added

Emergency Services

Admin can manage actual service contacts; Control Room can view the directory read-only for coordination.

In alignment

Reports and Intelligence

Reports are being aligned as history/accountability views, while Intelligence planning focuses on patterns, links, hotspots, and risk indicators.

Prepared

Server migration pack

Migration report, technical specification, and handover pack are prepared; PDF output should be regenerated after latest cleanup.

How CivitasWatch Feels by Role

The platform separates field capture, live coordination, source-of-truth administration, historical reporting, and future intelligence analysis.

Patroller mobile Control Room Admin registers Reports Intelligence / map

Patroller

Mobile
Logs in to
Start a patrol, update status, and capture field events.
Screens used
Login, Start Patrol, Active Patrol, Incident Response, Assistance, Infrastructure, End Patrol.
Decisions
Which patrol call sign, vehicle, crew, status, SAPS incident code, service type, and location to record.
Data flow
Events become live Control Room context and later report history.

Control Room

Live ops
Logs in to
Monitor live patrols and coordinate assistance.
Screens used
Live Overview, Active Patrols, Assistance Requests, Incidents, Directories, Patrol Reports, Map later.
Decisions
Which patrol needs attention, which service to contact, and what incident context matters now.
Data flow
Uses live patrol data and read-only directories, without editing Admin registers.

Admin

Registers
Logs in to
Maintain members, vehicles, contacts, and classification registers.
Screens used
Dashboard, Members, Patrollers, Vehicles, Emergency Services, Incident Codes, Service Types.
Decisions
Which source records are active, correct, and available to operational modules.
Data flow
Register values power Patrol dropdowns, Control Room lookup, Reports, and future Intelligence.

Reports

History
Logs in to
Review what happened and prepare accountability feedback.
Screens used
Monthly Safety Trends, Patroller Activity, Infrastructure, Assistance, Vehicle Usage, Patrol and Incident Reports.
Decisions
Which filters, periods, codes, suburbs, sectors, and exports are needed.
Data flow
Summarises historical operational data without becoming a live action screen.
